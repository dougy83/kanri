# Kanri — Editing Rules for AI Agents

## Files/Directories That Should NOT Be Edited

| Path | Reason |
|------|--------|
| `.nuxt/` | Auto-generated Nuxt build artifacts |
| `.output/` | Nuxt production build output |
| `node_modules/` | Dependencies |
| `dist/` | Build output |
| `src-tauri/gen/` | Auto-generated Tauri schemas |
| `LICENSES_3RD_PARTY.txt` | Auto-generated by rollup-plugin-license |
| `src-tauri/license.html` | Auto-generated |
| `yarn.lock` | Regenerated by yarn, commit as-is |
| `*.license` files | REUSE compliance — do not edit content, only modify alongside source |
| `.github/` templates | PR templates, issue templates, CI workflows |
| `src-tauri/Cargo.lock` | Rust dependency lock file |
| `.vscode/settings.json` | Personal editor settings |

## Generated / Build Artifacts

| Artifact | Source | When Generated |
|----------|--------|---------------|
| `.nuxt/` | `nuxt dev` / `nuxt generate` | Always during dev/build |
| `.output/` | `nuxt generate` | Production build |
| `dist/` | Tauri build | Production build |

**Do not manually edit these. If they appear in git, verify you're not committing build outputs.**

## Important Conventions

### Code Style
- **TypeScript for all `.ts` and `.vue` script setup** — avoid plain JS in new code
- **Vue 3 Composition API** with `<script setup lang="ts">` — no Options API
- **Pinia stores** use `defineStore` with composition API style (setup stores preferred)
- **SPDX license headers** at top of every file — required by REUSE spec. Format:
  ```
  <!-- SPDX-FileCopyrightText: Copyright (c) 2022-2026 trobonox <hello@trobo.dev> -->
  <!-- -->
  <!-- SPDX-License-Identifier: GPL-3.0-or-later -->
  ```
- **New components** auto-imported (Nuxt convention) — no manual registration needed
- **Aliased imports** use `@/` for project root (e.g., `import { X } from '@/stores/boards'`)
- **Icons** from `@phosphor-icons/vue` or `@heroicons/vue` — directly imported, not globally registered

### Naming
- Pinia stores: `useXxxStore` pattern
- Composables: `useXxx` pattern
- Components: PascalCase `.vue` files
- Pages: kebab-case or `[param].vue` for dynamic routes
- Events (mitt): camelCase strings

### State Access Rules
- **Never call `store.get()` or `store.set()` outside `stores/`** — enforced by custom ESLint rule `no-store-outside-stores.js`
- All Tauri store access goes through Pinia store actions
- Components use `storeToRefs()` for reactive state extraction

### i18n
- All user-facing strings via `$t('key')` or `t('key')` from `vue-i18n`
- Translation keys follow dot notation matching file structure: `pages.index.createBoardPrompt`, `components.sidebar.home`
- Default locale: `en`. New strings must be added to `en.json` first.
- `fallbackLocale: "en"`

## Preferred Patterns

### Adding State / Settings
1. Add state property in the relevant Pinia store
2. Add load logic in the store's `loadXxx()` action
3. Add setter action if user-configurable
4. Add to `kanriJsonSchema` in `types/json-schemas.ts` (for export/import)
5. Wire into UI in the relevant page/component

### Adding Board Data Operations
1. Add logic in `stores/boards.ts` (the pure data operation)
2. Expose through `composables/useBoard.ts` (the convenience wrapper with board ID binding)
3. Wire in the UI component

### Creating a New Modal
- Create component in `components/modal/`
- Use `v-show` for visibility (not `v-if`)
- Emit `closeModal`, `confirmAction`, etc.
- Use `emitter` pattern (`utils/emitter.ts`) for cross-component communication

### Adding a New Keyboard Shortcut
1. Add to `shortcutKeys` enum in `pages/kanban/[id].vue`
2. Add handler in `keyDownListener` function
3. Check `editCardModalVisible` to prevent shortcuts while editing

### Drag and Drop Integration
- Column drag: `Container` + `Draggable` from `vue3-smooth-dnd` in `pages/kanban/[id].vue`
- Card drag: within `components/kanban/Column.vue`, same library
- Drop handler calls `applyDrag()` from `utils/drag-n-drop.js`, then store reorder action

### Testing Pattern
- `test/setup.ts` mounts i18n and mocks `window.__TAURI_IPC__`
- Use `mountSuspended` from `@nuxt/test-utils/runtime`
- Test files co-located with pages (e.g., `pages/index.spec.ts`)
- `vitest.config.ts` uses `environment: "nuxt"` with `jsdom`

## Risky Areas

### 1. Tauri Store Persistence
- **Risk**: `boards.ts` auto-saves via `$subscribe` (100ms debounce). Heavy mutations can trigger race conditions on save.
- **Mitigation**: Keep mutations synchronous in store actions. The `save()` is async but debounced.
- **If editing**: Ensure `tauriStore.set()` + `tauriStore.save()` are called, or rely on the auto-save `$subscribe`.

### 2. Drag & Drop State
- **Risk**: `vue3-smooth-dnd` drop results must produce valid column/card arrays. The `applyDrag` utility can produce undefined items if payload lookup fails.
- **Mitigation**: After drop, call `reorderColumns` / `reorderCards` which replaces the entire array.
- **If editing**: Always test manual drag after changes. Check `getGhostParent` returns the correct container.

### 3. Board Background Images
- **Risk**: `useBackgroundImage` uses `@tauri-apps/plugin-fs` to check file existence. Missing files silently clear the background.
- **Risk**: `convertFileSrc` is Tauri-specific — will fail outside Tauri context (e.g., in tests).
- **If editing**: Wrap Tauri-specific calls in try-catch.

### 4. Auto-Save in boards Store
- **Risk**: `$subscribe` with `{ detached: true, deep: true }` fires on every nested mutation. The 100ms debounce means rapid edits may lose intermediate states.
- **Mitigation**: `save()` is called with `await`. Errors are logged but not user-visible.

### 5. Reactive Date Objects
- **Risk**: `Date` objects in Board/Card (createdAt, lastEdited, dueDate) can be serialized as strings by JSON/Tauri store. After store load, they may be strings, not Date objects.
- **Mitigation**: Use `new Date(value)` when reading date fields. The sorting functions in `utils/sorting.ts` handle this.

### 6. i18n Type Safety
- **Risk**: Translation keys are plain strings with no type checking. Typos in keys produce missing translations silently (fallback to key string).
- **If editing**: Verify translations exist in all locale files. Add to `en.json` first.

### 7. CSP in tauri.conf.json
- **Risk**: CSP rules (img-src, connect-src, style-src) are strict. Adding new asset types may require CSP updates.
- **If editing**: Test image loading and IPC after CSP changes.

## Validation Commands

```bash
yarn lint                # ESLint — must pass
yarn test                # Vitest — must pass
npm run tauri build      # Full production build (requires Tauri CLI + Rust toolchain)
yarn generate            # Nuxt static generation
```

**Quick check after edits**:
```bash
yarn lint && yarn test
```

> ⚠️ **Caution**: `yarn lint` runs with `--fix` by default, which auto-formats many files unrelated to your change. After running it, run `git diff --name-only` to verify only your intended files were modified, and `git checkout -- <file>` to restore any unrelated changes. Alternatively, use `npx eslint .` (without `--fix`) to just check for errors without auto-formatting.

## Expected Workflow After Edits

1. **If you changed stores/state** → run `yarn lint` (ensures ESLint rules), run `yarn test`
2. **If you changed UI/components** → run `yarn dev`, visually verify component
3. **If you changed i18n strings** → add to all 11 locale files (or at least `en.json`)
4. **If you changed import/export schemas** → update `types/json-schemas.ts` Zod schemas
5. **If you changed Tauri backend** → `npm run tauri dev` to verify Rust compilation + frontend
6. **If you changed drag-and-drop** → manually test column and card reordering
7. **If you added dependencies** → use `yarn add <pkg>`, commit updated `yarn.lock`
8. **If you modified license headers** → ensure SPDX identifiers are correct (GPL-3.0-or-later is primary)
9. **If you changed page transitions or layout** → check `layouts/default.vue` page transition classes
10. **Before committing** → verify `.nuxt/`, `.output/`, `dist/` are in `.gitignore`
